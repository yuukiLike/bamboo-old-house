# 竹林里的老屋 · Bamboo Old House

基于 Three.js 的交互式 3D 老屋场景，在竹林、木廊与房间之间漫游，感受晨昏、风雨和自然声景。使用 pnpm，可部署为静态网站。

## 目录

```text
bamboo-old-house/
├── src/          网页、Three.js 场景、实际使用的组件
├── public/       GLB 模型（贴图内嵌）、自然录音、备用画面和图标
├── dist/client/  构建后上传的完整网站
└── 根目录配置    pnpm、类型检查、构建与部署配置
```

`node_modules/`、`.next/` 和 `dist/` 由工具生成。类型检查缓存放在 `node_modules/.cache/`。源码保留在 `src/`，说明集中在本文件，不另外生成交付记录或压缩包。

## 运行与部署

环境：Node.js 24、pnpm 11.14.0。版本分别由 `.nvmrc` 和 `package.json` 指定。

```sh
pnpm install --frozen-lockfile
pnpm dev
```

开发地址以终端显示为准，通常为 `http://localhost:3000/`。构建与预览：

```sh
pnpm typecheck
pnpm lint
pnpm test
pnpm build
pnpm preview
```

预览地址默认为 `http://localhost:4175/`，以终端输出为准。部署时上传 **`dist/client/` 内的全部内容**，无需压缩。在线构建的安装命令为 `pnpm install --frozen-lockfile`，构建命令为 `pnpm build`，发布目录为 `dist/client`；Netlify 配置已包含这些设置。

[自然声音来源与致谢](public/audio/credits.md)

网页使用 `/models/` 和 `/_next/` 等根路径，按 `https://你的域名/` 部署。通过 HTTP/HTTPS 访问，不能双击 HTML 文件。线上无需 Blender、数据库或 Node.js 服务。`dist/server/` 是静态导出的构建中间产物，不需要上传。

## 从原项目同步资源

原项目位于同级 `../blender-two/`。先在原项目完成建模并导出网页资源，确认更新已经进入 `../blender-two/website/public/`，然后在本项目执行：

```sh
pnpm sync
```

该命令使用 macOS 自带的 `rsync`，单向复制原项目 `website/public/` 到本项目 `public/`，跳过 `.DS_Store` 与空目录，替换同名文件、补充新资源，再重新构建 `dist/client/`。它不回写原项目，也不自动删除本项目中额外的资源。完成后上传新的 `dist/client/`。如果把目录迁到 Windows，需要安装 rsync 或使用 WSL。

**修改 `.blend` 文件本身不会更新网页。** 必须先导出适合网页的 GLB；完整建模与导出步骤见原项目 [README](../blender-two/README.md)。这里保留实际副本，不依赖符号链接；普通安装、开发和构建不要求原目录存在，只有 `pnpm sync` 需要它。

同步范围需要区分：

| 原项目的更新 | 网页项目的处理 |
| --- | --- |
| 同名 GLB 的几何、内嵌贴图，或已有路径下的图片更新 | 执行 `pnpm sync` |
| 模型改名、增删模型，或修改地形、植物布局、相机、灯光、风和水 | 同时合并 `website/components/scene/` 到 `src/components/scene/` 的对应改动，再同步资源、检查并构建 |
| 页面或交互改动 | 对照 `website/app/`、`website/components/experience.tsx`，合并到 `src/` 中的对应位置 |
| 新代码引入新的依赖或组件 | 只补充实际使用的依赖和文件，再运行类型检查与构建 |

GLB 不包含网页的全部效果，所以 `pnpm sync` 明确只同步资源。代码更新需要按上表合并，避免覆盖网页项目自己的改动，或把未使用的模板组件重新带回来。不要用原项目的 `package.json`、锁文件、构建配置覆盖这里的配置。

## 保留内容与验证

技术栈为 React、TypeScript、Three.js、Tailwind CSS、Vinext/Vite。当前场景版本为 `bamboo-2026-09-13-trackpad`，模型与场景布局沿用原项目提交 `1dfca58`。

- 默认沿路走走，另有廊下望竹，以及包含八个屋内外地点的自由看看；保留360°环顾。
- 竹林望月、林间的风和井旁听雨各有独立机位；林间进入白天大风，井旁从晴天进入细雨。
- 清晨、白天、正午、傍晚、夜晚五个时段，与晴风、大风、细雨、暴雨四档天气组合；风雨只用档位，环境音量可调。
- 竹竿、连接枝叶和阴影随阵风一起弯曲回摆，落叶不规则飘落；不同地面、木井盖和靠外木结构有受雨后的材质反馈，屋檐积水后渐渐滴流。
- 手机时段条采用42px紧凑高度；自由看看没有额外外框，天气四按钮在竖屏以两行排列、短横屏以一行排列；横屏设置展开时暂时收起场景工具栏，保留完整可用的按钮。

六个模型位于 `public/models/`，贴图和缓冲数据已内嵌；建筑模型的 Meshopt 解码由现有场景代码完成。九段自然录音及其来源说明位于 `public/audio/`，声音在用户主动操作后播放。普通雨天无蝉鸣，细雨偶有蛙声，暴雨只保留风雨声。

资源同步保留本项目的静态导出、Netlify/Cloudflare配置、pnpm依赖和锁文件；不带入原项目的Blender作者文件、历史验收材料或未使用的模板组件。

此前资源同步时，50个对应源码/资源文件逐一比对一致，并在1440×900桌面、390×844手机竖屏、667×375手机横屏完成75项操作检查和81个界面状态检查。后续性能改动在本项目维护，不再要求场景源码与原项目逐字一致。

## 性能与维护

保留原有桌面与手机渲染分辨率（像素比分别最高 1.6 / 1.25）、植物数量和近处竹竿细节。性能处理包括：

- 在加载画面下准备白天、夜晚及室内 HDR 的实际绘制路径和灯光阴影，避免第一次切换时临时编译造成整页冻结。首次创建显卡着色器缓存仍可能耗时，加载准备完成后才启用场景控件。
- 根部风力从每个顶点重复计算改为按植物实例计算，弯曲、叶片铰接和法线仍由原有动画处理；视野剔除重新排列植物时同步更新风力，静止时不重复上传。
- 远处四种竹竿使用构建时生成的索引细节层级，单株三角形从 4820 / 4844 / 4876 / 4592 减为 1588 / 1276 / 1442 / 1012；误差预算为模型空间 5 毫米，保留原顶点、UV、法线和竹竿曲线。
- 干燥表面跳过湿润与水波计算，遮雨区域和竖直墙面跳过无效的雨点吸收纹理计算，避免暴雨时屋内也执行昂贵的地面效果；灯光照不到的植物批次省去室内点光源计算；室内先绘制遮挡竹林的墙面，静止镜头复用接触阴影。
- 沿路浏览直接跟随系统滚动，去掉章节附近不响应输入的停顿区，雨天不再叠加镜头延迟；退出环顾或恢复页面高度后，镜头重新同步实际滚动位置。未开启环顾时卸载阻塞滚轮的监听；进度和方位只更新对应的小块界面，避免每次触摸板输入重绘整页控件。
- 地点与观看模式切换使用120毫秒淡出、220毫秒淡入，在遮罩下更换机位；连续选择只提交最新目标，减少动态效果时立即切换，离开页面或失败时清理遮罩。手势环顾不经过转场，继续直接响应输入。
- 室内移动镜头时，接触阴影使用预热的低开销层；停下 120 毫秒后恢复原精度，并用 100 毫秒淡入。主画面分辨率、模型和抗锯齿不变，静止后的阴影继续复用；天空先利用房屋和地面遮挡，并跳过晴天无效的月面与雨云计算。
- 修复门两侧潮痕面与外墙仅相隔 0.016 毫米造成的深度冲突，将冲突面的 24 个顶点分开到 3 毫米，保留潮痕、UV、索引和材质。
- 修复住屋一灰泥柱与内墙仅相隔 0.010 毫米的冲突，只后退柱面 16 个顶点到 3 毫米间距，保留内外墙和窗洞。六个室内机位在最大视角、32:9 屏幕下的整个旋转近平面通过真实模型检查，无需移动机位或缩短裁切距离。
- 雨水地面细分共享相邻三角形的中点，遮雨查询复用遍历空间并优先检查近处墙面，保留薄窗与檐口的遮雨行为。

Mac 操作：沿路模式使用系统双指滚动；环顾模式双指滑动看四周、捏合缩放，拖动时画面跟随手指方向。支持 Chromium 的捏合滚轮事件和 Safari 的累计手势缩放；常规行/页滚轮及 Ctrl/Command + 滚轮仍可缩放，方向键、加减号、Home 和 Escape 保留。Safari 事件逻辑通过回归测试，实际浏览器验收使用 ego-lite。

`pnpm build` 会自动运行 `pnpm generate:lod`。更换 `public/models/bamboo.glb` 后，提交重新生成的 `src/components/scene/generated/bamboo-lod.json`；也可运行 `node scripts/generate-bamboo-lod.mjs --check` 检查模型与索引是否一致。简化工具只在构建时使用，不进入网页运行依赖。

本地生产构建已通过类型检查、lint、40项回归测试及浏览器检查，覆盖八个地点、六种观看方式和五时段 × 四天气组合，并检查390×844竖屏和667×375横屏。同机桌面采样中，原版首次切夜晚出现约 4.9 秒主线程长任务，优化后已检查的切换最长约 80 毫秒。该数字衡量切换阻塞，不是 FPS 或首次打开耗时，也不代表所有设备或线上部署状态。连续三轮切换后，画布、纹理、几何和着色器数量保持不变。

本轮触摸板回归在同一桌面浏览器发送30次细小原生滚轮输入，界面提交从旧版35次降为0次，进度条仍正常更新；环顾时滑动只改变方向，捏合只改变视野角度，页面缩放保持不变。室内连续35次移动均使用576×360接触阴影层，停止后只补一次1152×720细节层，画布始终为2304×1440，着色器数量不增长。门边修复通过原模型射线测试和正面/两侧实景检查。另检查了章节边界的小幅滚动、滚动途中进入/退出环顾，以及切换未完成时点击章节或返回；所有章节落点保持正确。八个地点完成整圈旋转、缩放及复位，室内细节阴影恢复时的贴图绑定也有独立回归覆盖。

在1440×900、像素比1.6的同一晴天屋前机位，14次绘制剔除前5次后，绘制加同步单像素读回的中位耗时由38.2毫秒降至27.0毫秒；这项诊断包含读回开销，不能当作实际帧率。

维护原则：根目录只放工具要求的配置和本说明；业务源码放入 `src/`；优先复用现有配置与 pnpm 命令，不增加重复记录、压缩包或无实际用途的组件。

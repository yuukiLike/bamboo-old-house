本地 issue 已建立；功能实现、测量与验收尚未开始。已确认需求与建议方案分别列出，待确认项不视为既定规格。

## 动机

不同语言的访客可以使用网站，并读到为对应语言单独编写的场景文字。

## 已确认的内容决定

- 中文、英文、日语的文案各自独立编写，不要求逐句对应，也不要求相同句数或表达顺序。
- 三种语言的文案由用户稍后提供。助手暂不代拟，不把现有中文的自动翻译作为最终内容。
- 内容结构为独立文案预留空间；具体段落与排版在收到文案后适配。

## 建议范围

- 提供中文、English、日本語的语言切换入口。
- 操作按钮、设置、加载状态、错误提示和无障碍名称使用对应语言。
- 场景叙事按语言独立保存和读取，修改一种语言不会要求其他语言同步改写。
- 首版建议保留相同的场景和导航结构；内容标识关联场景，不要求各语言的句子一一配对。
- 切换语言时保留场景、视角、时段、天气、声音及截图模式状态，不重新加载 3D 资源。
- 更新页面语言标记和标题，使其与当前语言一致。
- 建议首次访问默认中文，记住用户主动选择的语言；浏览器存储不可用时仍能切换。

首版不增加自动翻译服务、语言子路径或完整的多语言搜索优化。

## 开工前确认

- 收到用户文案后核对章节、出现位置与排版需求；目前不把相同章节结构作为已确认约束。
- 首次访问默认中文，还是根据浏览器语言选择？建议先默认中文，并记住手动选择。

## 建议验收标准

- [ ] 三种语言均可通过明确入口切换。
- [ ] 常用控件、设置面板、房间名称、截图操作、加载和失败提示均覆盖三种语言。
- [ ] 无障碍名称、页面语言标记和标题跟随语言变化。
- [ ] 各语言叙事能分别修改，不会覆盖其他语言版本，也不要求句数或表达顺序对应。
- [ ] 最终内容采用用户提供的三语言文案，并按实际文本验收排版。
- [ ] 切换语言不会重置当前体验，也不会重新加载 3D 资源。
- [ ] 刷新后保留主动选择；存储不可用时有确定默认值且页面正常运行。
- [ ] 英文较长文字、日文换行在桌面与手机预览中不遮挡主要操作，不产生横向溢出。

## 已查明的实现约束

- 文案主要集中在 `src/components/experience.tsx`，但加载提示、地点名称、天气名称和画布无障碍说明还分散在场景模块中。
- 多语言覆盖需要包含 `scene.ts`、`config.ts`、`weather-state.ts`、`view-controls.ts` 的用户可见文案，以及 `src/app/layout.tsx` 的页面元信息。
- 现有组件与类型系统足以支持固定三语言的小型内容表；是否增加依赖按实际复杂度决定。

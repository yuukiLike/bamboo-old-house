# 第二阶段：收紧遮雨索引候选

日期：2026-09-26。分支：`perf/tidewater-scene-optimizations-02-rain-index`。

系列入口：[3D 性能优化记录](../optimization-log.md)。父分支：`perf/tidewater-scene-optimizations`，父提交：`83baa2e119b40d0c76a69da874d83f2088f4ff5f`，已推送至 origin。

## 优化前记录

本节在第二阶段修改产品代码前保存。

第一阶段已经用固定雨向投影网格替换通用三角形树，并验证约 113 万顶点的湿润属性哈希一致。不过索引目前把三角形投影的整个矩形包围盒写入网格：细长或倾斜的三角形在盒内留下大量实际不相交的单元。现有数据为 10,926,248 个候选引用、88,085,980 字节数组容量（约 84.01 MiB）。每次查询仍会读取这些无效候选，再由精确求交排除。

待验证假设：在索引构建时以二维三角形边的半平面测试排除不可能相交的单元，复用已经计算的投影坐标。矩形网格不变，精确三角形求交不变；保守余量继续覆盖浮点误差和单元边界。此方案可能增加构建开销，只有查询与总耗时/容量的实测取舍合理时才保留。

保持边界：三个雨向、网格尺寸、原始模型、Float32 世界坐标、薄墙与缝隙、屋顶采样、射线长度、自交阈值、雨量和所有画质配置保持原样。不开启 computer-use。

用户在实施期间补充的画质约定已写入[固定记录](../optimization-log.md#画质与配置约定)：有画质取舍时保留原画质默认路径并提供配置选择。本阶段是保守的候选排除，继续以精确求交及全部雨水属性一致为验收门槛；若出现差异，先修复或回退，不能通过降低雨效精度掩盖。

验收方式：

- 与直接父提交使用相同真实 GLB 和当前 CPU 夹具，各执行三轮，比较总耗时、索引构建、表面计算与索引数组容量。
- 对所有雨水属性和植被输出做哈希对照，不能用计时改善代替输出一致性。
- 独立暴力求交测试继续覆盖变换、薄墙、缝隙和边界；增加长细斜三角形、单元角相交等针对本次排除逻辑的反例。
- 记录失败尝试；通过项目检查和生产构建，更新本地预览供查看。

## 实施与验证

已实现保守的三角形与网格单元相交判断，保留第一阶段的精确求交路径。

### 实际改动

[rain-occlusion.ts](../../../src/components/scene/rain-occlusion.ts) 在计算三角形投影包围盒时保留三个投影顶点，并根据三角形方向计算三条朝内的边法线。单元中心与半尺寸给出矩形沿各法线的最大覆盖范围；只有整个单元都在某条边外侧时，才不把该三角形写入此单元。

单元边界继续扩张原有的 `0.000001` 米余量。投影面积接近零时不做新增排除，沿用包围盒候选；正反两种三角形顶点顺序均受支持。距离、自交阈值以及 `Ray.intersectTriangle` 调用保持原样。减少候选也减少了后续排序和连续索引数组写入的工作。

CPU 采集脚本另修正了一处证据细节：读取 Git 源码时不再 `trim()` 文件尾部空白，让 `sourceHashes` 对应原始文件字节。前后版本使用同一份修正后的脚本重新测量，不修改历史证据文件；此改动不影响产品行为或计时区间。

### 与直接父阶段的三轮对照

设备和工具链：Apple M4、Darwin 27.0.0、Node v24.18.0、Three.js r185。使用相同 `architecture.glb`、生产墙面微调和湿润属性构建过程。计时口径与第一阶段一致：从遮雨构建开始，到建筑湿润属性完成，不含下载、贴图解码、GPU 渲染、shader 编译及整页其他初始化。

植被实现没有改变，同夹具中位数 `41.87 → 40.73 ms` 只作为控制组波动记录，**不计作本阶段植被优化收益**。同样不把本阶段与历史不同时间的第一阶段数据拼接成整页累计提速。

### 试验与验证记录

单轮试验合计为 `3004.83 ms`、候选 7,546,211 个，属性哈希一致；随后才进行上表中的三轮正式采集。该单轮保留在 `outputs/performance/tidewater-transfer-02/triangle-cell-trial.json`，不代替三轮数据。

新增边界测试的第一版出现一次差异。核对父版本后发现父版本同样不匹配；原因是测试 oracle 对已归一化射线再次归一化，精确三角形顶点上的浮点舍入发生变化。修正为与生产相同的单次归一化后，该边界在父版本和新版中均与独立暴力求交一致，新版完整反例集合通过。没有放宽断言、改碰撞阈值或跳过反例。

- `pnpm check` 通过：类型检查、oxlint、29 项测试及生成 LOD 校验。
- 当前分支 `pnpm build` 成功；固定父阶段在独立 worktree 用相同依赖构建成功。两版只有既有的大 chunk 提示。
- 两版 HTTP 入口、8 个入口 JS/CSS 资源及建筑 GLB 均返回 200；`git diff --check` 通过。未使用 computer-use。
- 本轮证据为纯 CPU 与几何属性对照，不是浏览器 FPS、GPU 帧时或截图验收。
